FRAMEWORK OVERVIEW

이 스킬은 자체 완결형 반응형 HTML 도구를 만드는 제작 프레임워크입니다. 단순한 색상 프리셋이 아니라, 사용자의 목적을 화면 구조와 상태로 바꾸는 방법, 디자인 토큰, 컴포넌트, 상태 관리, 접근성, 검증 기준까지 한 문서에 묶어 둔 실행 지침입니다.

핵심은 화면을 보기 좋게 꾸미는 것보다 사용자가 값을 조작하고, 변화가 즉시 연결되어 보이고, 결과를 정확히 이해하도록 만드는 것입니다. 계산기, 대시보드, 제품 구성기, 프로세스 탐색기, 인터랙티브 설명 같은 도구형 화면에 특히 적합합니다.

원본 스킬은 Three.js 3D를 기본값으로 제시하지만, 사용자 요구가 기본값보다 우선한다는 1절 규칙에 따라 이 웹사이트에서는 Three.js와 WebGL을 완전히 제외했습니다.

META

프런트매터

스킬의 식별자와 호출 조건

이름은 pixel-workbench-framework이고, 자체 완결형 반응형 HTML 경험을 Pixel Workbench 스타일로 만들거나 재스타일링할 때 쓰는 제작 스킬임을 선언합니다.

00

서문

전체 목표와 스킬의 성격

사용자가 조작하고, 변화를 관찰하고, 결과를 이해하는 흐름을 중심에 둡니다. npm 패키지가 아니라 디자인, 구조, 상태, 렌더링, 검증을 함께 규정하는 프롬프트형 제작 프레임워크입니다.

01

작업 계약과 우선순위

무엇을 우선해서 만들지 결정

사용자 요구를 기본값보다 우선하며, 기본 산출물은 바로 열 수 있는 단일 HTML입니다. 필요한 기능만 조합하고 불필요한 프레임워크나 백엔드를 추가하지 않도록 경계를 정합니다.

02

목적을 화면과 상태로 번역하기

요구사항을 구현 가능한 상태 모델로 변환

목적, 대상, 입력, 상태, 결과, 표현의 여섯 항목을 정리하고 계산기, 대시보드, 구성기, 프로세스 도구 등 목적별 화면 구성을 정합니다.

03

시각적 정체성과 두 테마

색과 형태의 디자인 시스템

먹색과 남색 배경, 1px 경계, 제한된 강조색, 모노스페이스 수치, 블록형 시각 요소를 기본으로 합니다. midnight-cyan과 graphite-signal 두 테마 토큰을 제공합니다.

04

타이포그래피·간격·그래픽

읽기 품질과 리듬을 수치화

폰트 스택, 간격 스케일, 제목과 본문 크기, 포커스 표시, 아이콘 규격을 정의합니다. 한글 본문은 선명한 시스템 폰트를 우선합니다.

05

레이아웃과 반응형 규칙

데스크톱부터 모바일까지 배치 기준

주 작업 영역과 보조 레일의 2열 구조를 기본으로 하며 900px 부근에서 단일 열로 전환합니다. 360px 폭에서도 핵심 조작이 유지되도록 요구합니다.

06

컴포넌트와 상태 표현

버튼, 결과, 표, 그래프의 공통 동작

상단 바, 조작 그룹, 결과 블록, 비교 카드, 그래프, 상세 설명 등 반복되는 UI 부품과 selected, disabled, loading, error 같은 상태 표현을 규정합니다.

07

레이어 계약

겹치는 UI의 z-index와 입력 처리

장면, 배경 장식, 라벨, 상태 안내, 도구, 오류 화면의 층위를 작게 고정해 입력 충돌을 막는 규칙입니다. 이번 웹사이트에서는 DOM 레이어 구조만 참고합니다.

08

Three.js 픽셀 3D 규칙

3D를 사용할 때의 렌더링 규칙

OrthographicCamera, 낮은 해상도 렌더, 단순 기하, 입력 조작, ResizeObserver, WebGL 실패 대응 등을 설명합니다. 이번 요청에서는 사용자가 Three.js 제외를 명시했으므로 사이트 실행 코드에는 포함하지 않았습니다.

09

단일 파일 구성과 의존성

배포 형태와 외부 의존성 통제

최종 사용자가 빌드 도구 없이 파일 하나를 바로 열 수 있어야 하며 외부 CSS, JS, 폰트, 이미지, CDN fetch를 기본적으로 금지합니다. 새 작업은 네이티브 HTML, CSS, JavaScript를 우선합니다.

10

상태와 로직의 구조

데이터와 화면을 분리하는 방법

config → state → derive(state) → render 흐름을 권장합니다. 계산을 DOM과 분리하고, 입력 검증 후 한 번 계산한 파생 결과를 모든 뷰에 공유하도록 합니다.

11

접근성과 읽기 품질

키보드, 대비, 터치, 감속 모션

의미 있는 HTML, 44px 수준의 터치 영역, 포커스 표시, 충분한 대비, aria-live의 절제된 사용, reduced motion 대응을 완료 조건에 포함합니다.

12

완료 조건과 검증 범위

완성 여부를 체크하는 기준

실제 단일 HTML인지, 오프라인에서 동작하는지, 주요 동작과 계산이 일치하는지, 360/768/1440px에서 깨지지 않는지 등을 확인하도록 합니다.

13

호출 예시와 문서만 사용하는 방법

스킬을 실제로 적용하는 사용법

설치된 스킬 이름을 직접 호출하는 예시와 Markdown 파일만 첨부해 사용하는 예시를 보여줍니다. 별도 등록이나 원본 HTML 없이도 문서 하나로 적용 가능하다는 뜻입니다.

14

작성 원칙의 근거

프레임워크가 어떤 원칙으로 정리됐는지 설명

두 참고 HTML의 패턴을 일반화했고, 외부 문서는 디자인 토큰이 아니라 지침 작성 방식의 참고로만 사용했다고 밝힙니다. 특정 모델, API 키, 요금제는 요구하지 않습니다.
